# Detailed source-mask contour reconstruction

The museum's original DP272838 image (701 x 1945) is now retained alongside the 225 x 624 thumbnail, under the same Met Open Access evidence. Its distinct SHA-256 and provenance are recorded. The detail benchmark checks that hash and crops the floral connector at source-pixel ROI (177,935,147,162). The source is Ottoman, attributed to Bursa, Turkey, not Ukrainian or Arabic.

The new cell-boundary contour adapter reuses existing four-connected component extraction. It traces boundary loops with deterministic right-turn handling of ambiguous diagonal corners, simplifies only collinear cell edges, retains holes, and emits observed reference geometry into the existing typed MotifGraph. The separate even/odd polygon rasterizer reconstructs the filled mask at pixel centres. Multiple loops remain in one reference element; this does not claim they are independently identified petals or stitch holes.

This goes beyond sparse polygon envelopes and horizontal row runs: the selected region reconstructs detailed visible outer ornament and negative spaces as closed contours. Segmentation currently uses an explicit colour rule: red ground iff R-G > 30 and R-B > 15. It separates the chosen colour mask, not expert-identified flowers, stems or leaves. Some holes and small components can reflect JPEG artefacts, textile texture or gold-coloured regions classified by the rule. No morphology removes them or invents missing geometry.

`npm run benchmark:motif:historical` includes this detailed source benchmark. It emits a source crop, original/contours/overlay comparison SVG, graph and report under `artifacts/motif-reconstruction/detail-met-445264`. The prior coarse six-corner floral envelope is evaluated against the same colour mask, as is a deliberate 2-source-pixel displacement. These measure mask representation fidelity, not independent historical or semantic accuracy. The report is retained under `docs/benchmarks/motif-detail-met-445264.json`.

Tests reconstruct every one of the 512 possible 3 x 3 binary masks, including diagonal adjacency and self-touching cases, plus an independently authored ring/isolated-pixel control with an expected hole count. They cover determinism, independent editable transforms, permission rejection, nonbinary inputs and open contour rejection. This tests pixel topology rather than mirroring the tracing implementation.

No canonical glyph geometry, manufacturing compiler or production gate is changed. Filled comparison SVGs are reference illustrations; contour run IR is not a digitized machine stitch plan. Remaining work includes independently reviewed segmentation, colour/layer separation, explicit internal stem and petal units, historical grammar extraction, Ukrainian permissions, rectification, physical calibration and sew-out. No training or production approval is claimed.

Local verification passed: `npm run verify:tesseract-worker` (145 engine tests, engine typecheck/build and production pilot, stitch-engine typecheck and 22 stitch tests) and `npm run benchmark:motif:historical` (four benchmarks). The detail colour mask has 9,267 selected pixels, three components and 65 loops (62 negative-winding loops). Reconstruction IoU is 1 and RMSE 0 against that mask; the coarse envelope IoU is 0.6036334275333064 and the two-pixel displacement control IoU is 0.7973235065942591. These values do not measure expert annotation accuracy. Remote CI success has not been checked for this increment.
